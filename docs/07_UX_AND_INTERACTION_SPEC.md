## §15.1 体验目标

系统必须降低四类认知负担：

1. 不知道问题到底在问什么；
2. 不知道为什么重要；
3. 不知道为什么推荐给我；
4. 不知道系统判断是否可信。

相关原则：（设计规范 §5.5）渐进式展开；（设计规范 §5.3）多维评价优于单一权威榜；（设计规范 §5.7）不确定性必须可见。

---

## §15.2 三层阅读深度

| 层级 | 时间 | 内容 |
|---|---:|---|
| 卡片正面 | 10–20 秒 | 一句话陈述、为什么重要、为什么推荐、状态 |
| 快速导览 | 2–3 分钟 | 背景、已知结果、可能切入方式、评分理由 |
| 研究档案 | 15 分钟以上 | 原始陈述、完整文献、证据链、版本和审核记录 |

（同一张问题卡应支持 20 秒、3 分钟和 15 分钟以上三种阅读深度的总原则见（设计规范 §5.5）。）

## §15.3 研究者端页面

### A. 首次设置

- 选择主领域和邻近领域；
- 选择熟悉方法；
- 选择偏好的结果类型；
- 选择背景学习成本；
- 选择稳健 / 平衡 / 冒险；
- 允许稍后修改或跳过。

（三种模式的定义与卡池混合策略见《docs/05_SCORING_AND_RANKING_SPEC.md》§13.6；研究者角色目标见（设计规范 §4.1）。）

### B. 今日抽卡

一次展示 3–5 张：

- 一张最匹配；
- 一张高重要性；
- 一张快速反馈；
- 一张邻近领域；
- 可选一张远距离偶遇。

页面必须说明每张卡属于哪种推荐理由。

（抽卡不是纯随机抽样，定义见（设计规范 §3.7）；Draw API 要求响应中的每个问题必须包含 `recommendation_reasons` 和 `evidence_confidence`，见（设计规范 §18.2）。）

### C. Problem Card 详情

首屏：

- 问题名称；
- 一句话陈述；
- 领域与类型；
- 开放状态及最后核验时间；
- 为什么重要；
- 为什么可能适合 AI；
- 为什么推荐给当前用户；
- 收藏、加入卡池、跳过。

展开区：

- 数学背景；
- 原始陈述；
- 规范化陈述；
- 已知结果；
- 问题关系；
- 证据与文献；
- 评分明细；
- 审核与版本历史。

（原始陈述与规范化陈述必须并列保存的要求见（设计规范 §5.2）；四个评分维度的定义见《docs/05_SCORING_AND_RANKING_SPEC.md》§13.2。）

### D. 问题探索器

- 搜索；
- 按领域、问题类型、状态、工具和背景成本筛选；
- 以列表为主，避免密集卡片墙；
- 支持保存筛选器；
- 支持查看问题族与关系。

（问题族定义见（设计规范 §3.3）。）

### E. 个人卡池

- 收藏；
- 准备尝试；
- 已跳过；
- 关注状态变化；
- 导出问题资料包；
- 未来提交到 Solver Backend。

（Solver Backend 是外部可插拔执行器，不拥有 Problem Card 的主数据权，见（设计规范 §6.2、§17）。）

## §15.4 审核者端页面

- 待核验问题队列；
- 原文与规范化陈述并排 diff；
- 开放状态证据时间线；
- 疑似重复并排比较；
- 重要性和 AI 友好性证据；
- 一键作出有限枚举决定；
- 可选文字修改；
- 查看 Agent 运行和来源；
- 冲突升级队列。

（审核者只处理高价值判断、有限枚举决定的取值范围见（设计规范 §12）P7；审核者角色目标见（设计规范 §4.2）；专家原始决定不可被后续 Agent 覆盖。）

---

## §15.5 交互原则（九条，全部保留）

- 所有反馈可撤销；
- 不使用无限滚动作为核心抽卡机制；
- 不用稀有度颜色暗示数学价值；
- 不用小数分数制造精确幻觉；
- 不因“抽卡”概念引入诱导消费式动画；
- 键盘可操作，颜色不是唯一状态信号；
- 数学公式支持复制 LaTeX；
- 来源链接和核验日期始终可达；
- 错误报告入口必须显眼。

（允许的用户反馈动作枚举与 `undo` 语义见（设计规范 §12）P9；伪精确禁令见《docs/05_SCORING_AND_RANKING_SPEC.md》§13.1；点击率不得直接解释为数学重要性。）
