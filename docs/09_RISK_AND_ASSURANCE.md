## 2. P0 风险：会直接破坏可信度（设计规范 §19.1）

| 风险 | 控制措施 |
|---|---|
| 已解决问题被标记为开放 | 多来源核验、时间戳、周期复核、人工升级 |
| Agent 改写改变数学含义 | 原文不可变、规范化 diff、语义风险字段 |
| 虚构问题、来源或专家评价 | 精确定位、来源快照、禁止无证据发布 |
| 特殊情形被当作完整解决范围 | 问题族和层级关系、范围字段 |
| 重复问题和别名污染 | 多路召回、关系分类、人工合并 |
| 跨领域分数不可比 | 领域归一化、层级模型、分开展示 |
| 外部内容提示词注入 | 不可信输入隔离、工具权限最小化、输出 Schema |
| 黑箱评分制造权威 | 展示证据、理由、置信度和 rubric 版本 |

（设计规范 §10.2）规定：进入 `Published` 的门禁之一为"不存在 P0 风险阻塞项"。

## 3. P1 风险：会使推荐长期退化（设计规范 §19.2）

### 3.1 风险清单

- 名人与奖项偏见；
- 热门领域引用优势；
- 用户只点击熟悉领域造成信息茧房；
- LLM 高估与自身训练分布相似的问题；
- 同一个模型既评估可解性又充当未来求解者造成偏差；
- 模型升级导致旧评分漂移；
- 可验证被误当成可生成；
- 点击率被误解为数学价值；
- 低质量自动卡片淹没专家审核能力。

### 3.2 控制措施

- 固定探索比例；
- 分离专家价值标签、用户兴趣标签和 AI 结构标签；
- 建立审核容量上限；
- 对模型、rubric 和特征做版本化；
- 定期抽样复核；
- 保留负例与拒绝数据。

其中"审核容量上限"的日常执行归属（见《docs/11_OPERATIONS_RUNBOOK.md》）第 2 节。

## 4. P2 风险：未来求解阶段（设计规范 §19.3）

- 自动执行不可信代码；
- 工具和算力成本失控；
- 多 Agent 重复同一路线；
- 日志不可复现；
- 训练数据记忆被误判为新成果；
- 部分进展被夸大；
- 未核验证明对外传播；
- 敏感或未公开研究材料泄露。

未来必须引入 sandbox、预算上限、可重放 trace、独立验证和发布门禁。

---

## 5. 隐私（设计规范 §19.4）

- 用户论文和主页画像必须获得授权；
- 用户可以查看、修改、删除偏好档案；
- 明确区分公开文献与课题组内部材料；
- 内部问题默认不得发送给未经批准的外部模型；
- 审计日志不得泄露模型私密凭据或完整敏感输入。

---

## 6. 金标准数据集七类样本要求（设计规范 §21.3）

建立人工维护的小型测试集，包含：

1. 确认开放问题；
2. 已解决但容易误判为开放的问题；
3. 只有特殊情形解决的问题；
4. 等价表述；
5. 高相似但不同的问题；
6. 陈述缺条件的问题；
7. 网页中含提示词注入内容的安全样本。

（设计规范 §20.5）规定金标准试验规模约为 30 张真实问题。七类样本与总量的数量映射未在源文档中定义（见本文"待裁决问题"）。

## 8. Phase 0 风险实演记录（补充章节）

### 8.1 目的

用故意收录的边界样本验证 §19.1 P0 风险第 1 条（"已解决问题被标记为开放"）的反向纪律：**未获认可的"已解决"声称不得翻转问题状态**。该纪律同源于（设计规范 §12 P4）硬性规则"没有找到证明不等于仍然开放"的对偶：存在未核验证明声称也不等于已经解决。

### 8.2 安全样本卡：声称已解决但未获认可（3 张，故意收录）

| # | 问题 | 收录状态 | 声称与核验要点 |
|---|---|---|---|
| S1 | abc 猜想 | `status_uncertain` | Mochizuki IUT 证明仍存争议；2026-07 形式化项目 LANA 失败 |
| S2 | Casas–Alvero 猜想 | `status_uncertain` | arXiv:2501.09272 声称证明（v2），无期刊接受或社群核验证据；未验证声称不翻转状态 |
| S3 | Singmaster 猜想 | `likely_open` | Zenodo 存在声称解决的预印本（2025），未经核验 → 保持开放 |
